## 1. The Basics of Matrix Multiplication

At its core, a **matrix** is just a rectangular grid of numbers organized into **rows** (horizontal) and **columns** (vertical). We describe its shape as:

$$
\text{Shape} = \text{Rows} \times \text{Columns}
$$

For example, a matrix with $2$ rows and $3$ columns has a shape of $2 \times 3$.

### The Dimension Rule

You cannot multiply just any two matrices together. There is one simple rule:

<Callout type="note" title="The Golden Rule of Matrix Multiplication">
To multiply matrix $A$ by matrix $B$, the **number of columns in $A$** must equal the **number of rows in $B$**:

$$
(M \times K) \times (K \times N) = (M \times N)
$$

The shared inner dimension $K$ matches and collapses, leaving behind an output matrix of size $M \times N$.
</Callout>

### How the Calculation Works (Row Meets Column)

To find a specific number in the output matrix at **row $i$** and **column $j$**:

1. Take **row $i$** from the first matrix $A$.
2. Take **column $j$** from the second matrix $B$.
3. Multiply their numbers pair-by-pair.
4. Add the products together.

$$
C[i, j] = \sum_{k} A[i, k] \cdot B[k, j]
$$

For instance, consider multiplying a $2 \times 3$ matrix by a $3 \times 2$ matrix:

$$
\begin{bmatrix}
1 & 2 & 3 \\
4 & 5 & 6
\end{bmatrix}
\times
\begin{bmatrix}
7 & 8 \\
9 & 1 \\
2 & 3
\end{bmatrix}
=
\begin{bmatrix}
C[0,0] & C[0,1] \\
C[1,0] & C[1,1]
\end{bmatrix}
$$

To find $C[0, 0]$, take **Row 0** of $A$ ($[1, 2, 3]$) and **Column 0** of $B$ ($\begin{bmatrix} 7 \\ 9 \\ 2 \end{bmatrix}$):

$$
C[0, 0] = (1 \times 7) + (2 \times 9) + (3 \times 2) = 7 + 18 + 6 = 31
$$

The result is a $2 \times 2$ matrix. Notice how using different numbers of rows and columns ($2 \times 3$ and $3 \times 2$) makes it obvious which dimension controls the output shape ($2 \times 2$).

## 2. How Computers Store Matrices in Memory

When we write math on paper or in code, we visualize a matrix as a 2D table with rows and columns.

However, **computer hardware does not have 2D memory**. Physical RAM is strictly a **flat, one-dimensional line of memory addresses** numbered $0, 1, 2, 3, \dots$.

So how do libraries like **NumPy** and **PyTorch** store a 2D matrix in a 1D line of memory?

### Row-Major (C-Contiguous) Layout

By default, NumPy and PyTorch store matrices in **Row-Major order**. This means the computer lays down the elements **row by row**:

1. First, it stores all elements of **Row 0** side-by-side.
2. Directly after that, it stores all elements of **Row 1**.
3. Directly after that, it stores all elements of **Row 2**.

```text
2D Matrix:
[ 12, 25, 38 ]   <- Row 0
[ 41, 56, 63 ]   <- Row 1
[ 74, 87, 99 ]   <- Row 2

Stored in 1D Memory:
[ 12, 25, 38, 41, 56, 63, 74, 87, 99 ]
   Row 0        Row 1        Row 2
```

### The Address Formula: How Any $(i, j)$ Element is Found

Since the computer only knows 1D memory indices, how does it locate element $(i, j)$? It calculates the offset using simple arithmetic:

$$
\text{Memory Index} = (i \times \text{number of columns}) + j
$$

For a $3 \times 3$ matrix:
- To access **Row 1, Column 2**:
  $$\text{Index} = (1 \times 3) + 2 = 5$$
  The computer jumps straight to position $5$ in the memory buffer!

### Understanding Strides

In PyTorch and NumPy, this jumping behavior is controlled by **strides**. A stride tells the tensor how many memory slots to skip to move forward by 1 step along a dimension:

- **Moving to the next column** takes $1$ step in memory: `stride[1] = 1`.
- **Moving to the next row** skips an entire row of $3$ numbers: `stride[0] = 3`.

```python
import torch

# Create a 3x3 matrix
x = torch.tensor([[12, 25, 38],
                  [41, 56, 63],
                  [74, 87, 99]])

print(x.stride())        # Output: (3, 1)
print(x.is_contiguous()) # Output: True
```

## 3. Multiplying Matrices in Code

Now that we know how matrices are stored in memory, how do we multiply two matrices in code?

To multiply matrix $A$ ($M \times K$) by matrix $B$ ($K \times N$), the program loops through every row of $A$ and every column of $B$, computing the sum of their products.

### The Algorithm in Python

Here is the standard 3-loop implementation from first principles:

```python
def matmul(A, B):
    M = len(A)       # Number of rows in A
    K = len(A[0])    # Columns in A == Rows in B
    N = len(B[0])    # Columns in B

    # Initialize result matrix C of size M x N with zeros
    C = [[0 for _ in range(N)] for _ in range(M)]

    # Loop over every row of A
    for i in range(M):
        # Loop over every column of B
        for j in range(N):
            # Compute dot product of row A[i] and column B[j]
            total = 0
            for k in range(K):
                total += A[i][k] * B[k][j]
            C[i][j] = total

    return C
```

### Translating Loops to Flat 1D Memory

Since the computer stores matrices as flat 1D memory buffers, the loop indices $(i, j, k)$ turn into direct 1D memory addresses based on each matrix's number of columns:

- **Matrix $A$ ($2 \times 3$):** Each row has $3$ numbers $\implies \text{Address in } A = (i \times 3) + k$
- **Matrix $B$ ($3 \times 2$):** Each row has $2$ numbers $\implies \text{Address in } B = (k \times 2) + j$
- **Matrix $C$ ($2 \times 2$):** Each row has $2$ numbers $\implies \text{Address in } C = (i \times 2) + j$

In pure flat-memory code, the innermost loop evaluates:

```python
# A has shape 2x3 (size 6), B has shape 3x2 (size 6), C has shape 2x2 (size 4)
for i in range(2):        # Row of A (0 or 1)
    for j in range(2):    # Column of B (0 or 1)
        for k in range(3):# Dot-product term (0, 1, or 2)
            addr_A = i * 3 + k  # advances by +1 in RAM (consecutive)
            addr_B = k * 2 + j  # advances by +2 in RAM (jumps across rows of B)
            C_mem[i * 2 + j] += A_mem[addr_A] * B_mem[addr_B]
```

### A Note on Performance: Why Memory Access Patterns Matter

Look closely at the memory strips as the inner loop runs:

1. **For Matrix A:** The inner loop reads `A_mem[i * 3 + k]`. Because $k$ increases by $1$, the computer reads **adjacent memory slots**. This is extremely fast because modern CPUs fetch whole blocks of contiguous memory (cache lines) in one go!
2. **For Matrix B:** The inner loop reads `B_mem[k * 2 + j]`. Every time $k$ increments, the computer must **jump across memory lines by 2 slots**.

In deep learning hardware (like NVIDIA GPUs and PyTorch kernels), understanding this memory layout is the key to writing fast code. For example, transposing matrix $B$ before multiplication turns those jumping memory reads into fast consecutive reads!
